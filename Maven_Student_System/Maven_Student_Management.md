# Maven Student Management System — Complete Ubuntu Lab Guide

This guide explains how to build a Maven-based Student Management System on Ubuntu from scratch. Follow the steps in order, execute the commands as provided, and create each file at the specified location.

## Lab Objectives

- Install and configure Java 17 and Maven on Ubuntu.
- Create a Maven project with the required project coordinates.
- Add Apache Commons Lang and use its utility methods in Java.
- Add JUnit 5 with test scope and write unit tests.
- Compile and test the application using Maven.
- Inspect direct and transitive dependencies using `mvn dependency:tree`.
- Exclude a transitive dependency through `pom.xml`.
- Verify that the excluded dependency no longer appears in the dependency tree.
- Rebuild and test the project after the exclusion.

## Step 1 — Open Ubuntu Terminal

Open the Terminal application using:

```text
Ctrl + Alt + T
```

Check the Ubuntu version:

```bash
lsb_release -a
```

Update the package lists:

```bash
sudo apt update
```

Enter your Ubuntu password if requested. The terminal may not display characters while you type your password; this is normal.

## Step 2 — Install Java 17 and Maven

Execute:

```bash
sudo apt install -y openjdk-17-jdk maven
```

Verify Java:

```bash
java -version
```

Verify the Java compiler:

```bash
javac -version
```

The compiler should report Java 17.

Verify Maven:

```bash
mvn -version
```

Confirm that Maven is installed and uses Java 17.

**Do not continue until Java and Maven are installed successfully.**

## Step 3 — Create the Maven Project

Execute the following command to generate the project:

```bash
mvn archetype:generate \
  -DgroupId=com.college \
  -DartifactId=student-management \
  -Dversion=1.0-SNAPSHOT \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DinteractiveMode=false
```

Wait for Maven to finish generating the project. The first execution may take some time because Maven downloads required artifacts.

Enter the project directory:

```bash
cd student-management
```

Verify the current directory:

```bash
pwd
```

The path should end with:

```text
student-management
```

Inspect the generated files:

```bash
find . -maxdepth 5 -type f
```

## Step 4 — Configure `pom.xml`

From inside the `student-management` directory, execute the following command to create or replace `pom.xml`:

```bash
cat > pom.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.college</groupId>
    <artifactId>student-management</artifactId>
    <version>1.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>

        <!-- Apache Commons Lang: direct compile dependency -->
        <dependency>
            <groupId>org.apache.commons</groupId>
            <artifactId>commons-lang3</artifactId>
            <version>3.18.0</version>
        </dependency>

        <!-- JUnit 5: direct test dependency -->
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.12.2</version>
            <scope>test</scope>
        </dependency>

    </dependencies>

    <build>
        <plugins>

            <!-- Compile using Java 17 -->
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
            </plugin>

            <!-- Run JUnit 5 tests -->
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-surefire-plugin</artifactId>
                <version>3.5.2</version>
            </plugin>

        </plugins>
    </build>

</project>
EOF
```

Verify the configuration:

```bash
cat pom.xml
```

The project coordinates must be:

| Property | Value |
|---|---|
| Group ID | `com.college` |
| Artifact ID | `student-management` |
| Version | `1.0-SNAPSHOT` |
| Java release | `17` |
| Commons Lang version | `3.18.0` |
| JUnit Jupiter version | `5.12.2` |

At this stage, the POM includes Commons Lang and JUnit. Do not add the dependency exclusion yet.

## Step 5 — Create the Java Source Folders

Execute:

```bash
mkdir -p src/main/java/com/college
mkdir -p src/test/java/com/college
```

Remove the default test generated by the Maven archetype if it exists:

```bash
rm -f src/test/java/com/college/AppTest.java
```

This removes only the generated `AppTest.java` file. It does not delete the project or any other source files.

## Step 6 — Create `Student.java`

Create the file at:

```text
src/main/java/com/college/Student.java
```

Execute:

```bash
cat > src/main/java/com/college/Student.java <<'EOF'
package com.college;

import org.apache.commons.lang3.StringUtils;

public class Student {

    private final String name;
    private final int rollNumber;

    public Student(String name, int rollNumber) {
        this.name = name;
        this.rollNumber = rollNumber;
    }

    public String getName() {
        return name;
    }

    public int getRollNumber() {
        return rollNumber;
    }

    public boolean hasValidName() {
        return StringUtils.isNotBlank(name);
    }

    public String getDisplayName() {
        return StringUtils.capitalize(name);
    }
}
EOF
```

### Explanation

- `getName()` returns the original student name.
- `getRollNumber()` returns the student's roll number.
- `hasValidName()` uses Apache Commons Lang's `StringUtils.isNotBlank()` method to reject null, empty, and whitespace-only names.
- `getDisplayName()` uses `StringUtils.capitalize()` to capitalize the first character of the name.

For example, a student whose name is `akash` has the display name `Akash`.

## Step 7 — Create `App.java`

Create the main application at:

```text
src/main/java/com/college/App.java
```

Execute:

```bash
cat > src/main/java/com/college/App.java <<'EOF'
package com.college;

public class App {

    public static void main(String[] args) {

        Student student = new Student("akash", 101);

        System.out.println("Student Management System");
        System.out.println("-------------------------");
        System.out.println("Roll Number: " + student.getRollNumber());
        System.out.println("Name: " + student.getDisplayName());
        System.out.println("Valid Name: " + student.hasValidName());
    }
}
EOF
```

This class creates a student and displays the student's roll number, formatted name, and name-validation result.

## Step 8 — Create `StudentTest.java`

Create the JUnit test at:

```text
src/test/java/com/college/StudentTest.java
```

Execute:

```bash
cat > src/test/java/com/college/StudentTest.java <<'EOF'
package com.college;

import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.junit.jupiter.api.Assertions.assertFalse;

public class StudentTest {

    @Test
    void testStudentName() {
        Student student = new Student("akash", 101);

        assertEquals("akash", student.getName());
        assertEquals("Akash", student.getDisplayName());
        assertEquals(101, student.getRollNumber());
        assertTrue(student.hasValidName());
    }

    @Test
    void testBlankStudentName() {
        Student student = new Student("   ", 102);

        assertFalse(student.hasValidName());
    }
}
EOF
```

### Explanation

The test class contains two unit tests:

1. `testStudentName()` verifies the student's name, display name, roll number, and name-validation result.
2. `testBlankStudentName()` verifies that a whitespace-only name is considered invalid.

The `@Test` annotation identifies methods that JUnit should execute as tests.

## Step 14 — Add the Transitive Dependency Exclusion

Now replace `pom.xml` with the updated version below.

The only dependency-related change is the addition of an `<exclusions>` section under the JUnit dependency.

Execute:

```bash
cat > pom.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.college</groupId>
    <artifactId>student-management</artifactId>
    <version>1.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>

        <!-- Apache Commons Lang: direct compile dependency -->
        <dependency>
            <groupId>org.apache.commons</groupId>
            <artifactId>commons-lang3</artifactId>
            <version>3.18.0</version>
        </dependency>

        <!-- JUnit 5: direct test dependency -->
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.12.2</version>
            <scope>test</scope>

            <!-- Exclude a transitive dependency -->
            <exclusions>
                <exclusion>
                    <groupId>org.junit.jupiter</groupId>
                    <artifactId>junit-jupiter-params</artifactId>
                </exclusion>
            </exclusions>
        </dependency>

    </dependencies>

    <build>
        <plugins>

            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
            </plugin>

            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-surefire-plugin</artifactId>
                <version>3.5.2</version>
            </plugin>

        </plugins>
    </build>

</project>
EOF
```

Verify the updated configuration:

```bash
cat pom.xml
```

Confirm that the `<exclusions>` section appears inside the JUnit dependency.

## Step 15 — Verify the Exclusion

Run the dependency tree again:

```bash
mvn dependency:tree
```

The following dependency should no longer appear:

```text
org.junit.jupiter:junit-jupiter-params
```

To inspect only that dependency, execute:

```bash
mvn dependency:tree -Dincludes=org.junit.jupiter:junit-jupiter-params
```

After the exclusion, the filtered tree should contain no matching dependency nodes. Maven may still print its normal build information.

This verifies that the exclusion took effect.

### Why does the test still work?

Our test class uses the standard JUnit `@Test` annotation and assertion methods. It does not use parameterized tests, so excluding `junit-jupiter-params` should not affect the tests in this lab.

## Step 18 — Understand the Maven Concepts

### 18.1 Direct Dependency

A direct dependency is a library explicitly declared in your project's `pom.xml`.

Example:

```xml
<dependency>
    <groupId>org.apache.commons</groupId>
    <artifactId>commons-lang3</artifactId>
    <version>3.18.0</version>
</dependency>
```

Here, `commons-lang3` is a direct dependency because we declared it ourselves.

### 18.2 Transitive Dependency

A transitive dependency is a library Maven brings into the project because another dependency requires it.

For example:

```text
student-management
    |
    └── junit-jupiter
            |
            ├── junit-jupiter-api
            ├── junit-jupiter-params
            └── junit-jupiter-engine
```

We declare `junit-jupiter`, while Maven resolves the dependencies required by it.

### 18.3 Dependency Scope

Dependency scope determines when and where a dependency is available.

| Scope | Meaning |
|---|---|
| `compile` | Available during compilation and runtime; this is the default scope |
| `test` | Available for compiling and running tests, not for the normal application runtime |
| `provided` | Available for compilation and expected to be provided by the runtime environment |
| `runtime` | Not needed for compiling the application's source code, but needed at runtime |

Our JUnit dependency uses:

```xml
<scope>test</scope>
```

JUnit is required for running unit tests, not for the normal execution of the Student Management application.

### 18.4 Dependency Exclusion

A dependency exclusion prevents a specified transitive dependency from being brought in through the dependency under which the exclusion is declared.

Example:

```xml
<exclusions>
    <exclusion>
        <groupId>org.junit.jupiter</groupId>
        <artifactId>junit-jupiter-params</artifactId>
    </exclusion>
</exclusions>
```

Before the exclusion:

```text
student-management
    |
    └── junit-jupiter
            |
            ├── junit-jupiter-api
            ├── junit-jupiter-params
            └── junit-jupiter-engine
```

After the exclusion:

```text
student-management
    |
    └── junit-jupiter
            |
            ├── junit-jupiter-api
            └── junit-jupiter-engine
```

This illustrates the intended change. The actual tree may include other dependencies, and an excluded artifact could still be introduced through a different dependency path.

## Conclusion

The Student Management System demonstrates the Maven project lifecycle, Java compilation, JUnit unit testing, dependency inspection, and dependency exclusion.

Remember:

- **Direct dependency:** Declared by us.
- **Transitive dependency:** Brought in through another dependency.
